## Intent

Goal: publish the verified filter-subscription feature and quality hardening as
`v1.1.0` from the reviewed `master` merge commit.

Success criteria:

- Changelog contains a dated `1.1.0` section and an empty `Unreleased` section.
- PR #3 is clean, independently verified, merged through GitHub, and all
  required CI checks succeed.
- The local and remote `master` resolve to the merge commit before tagging.
- An annotated `v1.1.0` tag points to that exact commit.
- A non-draft, non-prerelease GitHub Release exists for `v1.1.0` with concise
  consumer-facing notes.
- The released Composer metadata is discoverable from the public package
  registry when its normal synchronization completes.

Scope:

- Release changelog, readiness checks, PR merge, annotated tag, GitHub Release,
  and post-release verification.

Out of scope:

- Additional runtime features or API changes.
- Manual Packagist publication configuration changes.
- Backport releases or merging unrelated work.

Constraints and dependencies:

- PHP 8.1 remains the minimum supported runtime.
- The release must include exactly the reviewed PR history.
- Registry synchronization may lag behind the GitHub tag and release.

## Dependency order

R1-T1 prepares the release candidate. R1-T2 independently verifies it. R1-T3
merges only after QA and CI pass. R1-T4 tags/releases the verified merge commit.
R1-T5 confirms the public artifacts and closes the epic.

### R1-T1. Prepare the release candidate

Status: `completed`

Goal: make PR #3 a complete `v1.1.0` release candidate.

Scope:

- Date the changelog release section.
- Verify Composer metadata, dependency advisories, release version vacancy,
  and the full test/quality matrix.
- Push release preparation through PR #3.

Out of Scope:

- Merge, tag, or release creation.

DoR:

- Version `1.1.0` follows from the additive public API and is authorized.

DoD:

- Release-prep commit is present in PR #3.
- PR checks pass after the commit.
- No known dependency advisory or version conflict remains.

AC:

- Given the changelog, when consumers inspect `1.1.0`, then filter support and
  delivery hardening are described under the release date.
- Given the candidate commit, when all project checks run, then they pass on
  the supported matrix.

Dependencies:

- PR #3 and GitHub access.

Notes/Risks:

- Composer packages obtain their version from the VCS tag; no version field is
  added to `composer.json`.
